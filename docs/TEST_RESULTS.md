## ビルド・単体テスト

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
.\gradlew.bat installDebug
```

最終ビルド・実機インストールは `BUILD SUCCESSFUL`。単体テスト27件（時計・同期状態8件、NTPパケット16件、設定保存3件）が全件成功しました。Lintは0エラー・8警告で、警告は固定した安定版依存ライブラリとGradleに対する更新通知です。詳細は `app/build/reports/tests/testDebugUnitTest/index.html`、`app/build/reports/lint-results-debug.html` を参照してください。

設定保存テストの反復中に、初回読込直後の保存と新しいデータ購読が重なる場合のタイムアウトを検出しました。初期化後もDataStoreの購読を維持し、保存待ちスナップショットを最新値へ集約するよう変更しました。修正後、設定保存テスト3件を別々のテストプロセスで5回連続実行し、全て成功しました。テストは一時ファイルへの実際の書込みとDataStoreインスタンスの再作成による復元を確認しています。

## 実機で確認した項目

| 項目 | 結果 |
| --- | --- |
| 起動時NTP同期 | `ntp.nict.jp` への同期成功。初回採用RTT 22.176ms、概算誤差約±12ms |
| ミリ秒表示 | JST・24時間の `HH:mm:ss.SSS` 表示を確認 |
| Ingress上で表示 | 起動画面およびスキャナー画面上に小型時計を表示 |
| バックグラウンド維持 | 別アプリへ切り替えてもForeground Serviceと時計の表示が継続 |
| ドラッグ | 位置移動・指を離した後の保存を確認 |
| 短いタップ | 補正パネルを開閉でき、時計の位置は変化しない |
| ＋1ms / −1ms | 0→+1→0→−1msの変更と、設定画面への即時反映を確認 |
| 通常表示に戻る | 閉じた後は時計のウィンドウ1個だけになることを確認 |
| 端付近での操作 | 上端付近では操作パネルを空き領域へ移動 |
| 回転 | 縦→横→縦で時計と操作パネルが可視領域内に収まることを確認。回転設定は元に戻した |
| タッチ通過 | 時計の外側をタップして、背後のAndroid設定アプリ内で画面遷移できることを確認 |
| プロセス再起動 | 強制終了・再起動後も補正値・移動位置が復元され、時刻は新たに同期されることを確認 |
| ON/OFF設定の復元 | ONにして強制終了した後、アプリ画面を開くと時計表示が復元することを確認 |
| 停止時の後片付け | OFFにするとサービスと全オーバーレイが削除されることを確認。検証後はOFFにした |
| 再同期失敗 | `127.0.0.1` への再同期でエラーと `DEGRADED` を表示し、前の同期時計を継続 |
| 初回同期失敗 | 到達不能な同期先を保存してプロセスを再起動すると `UNSYNCED` と `--:--:--.---` を表示。クラッシュや端末時計への代替なし |
| 失敗から復帰 | 同期先を `ntp.nict.jp` に戻して手動再同期すると `SYNCED` に復帰 |
| 表示位置・補正リセット | 設定画面のリセットで初期位置・0msへ復帰 |
